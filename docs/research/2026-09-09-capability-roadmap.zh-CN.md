# SheetDelta 可建设能力调研与路线图

调研日期：2026-09-09。定位：**面向业务数据导入、校验、对账和导出的 Excel/CSV 工具包**。

核对基线：本地 `master` 提交 `a4ccaef3344118890e2fe4ffc41138009c473d4f`，对应 0.4.0 发布代码。本文是建设建议，不是已发布 API 清单，也不是对版本或工期的承诺。

建议先完成“导入文件 → 明确映射 → 校验并定位问题 → 导出错误文件 → 修正后重试 → 对账并导出结果”这一条完整流程。后续优先建设可复用规则、业务报表和大文件处理。保留一个 `sheetdelta-core` 包，通过子路径按需导入。

## 1. 调研如何使用

本次对照了 8 个开源项目的官方仓库/文档，以及 GitHub Issue、Discussion、公开用户讨论和格式文档。来源共 23 项，见文末。没有根据星数、搜索排名或单条帖子推算需求规模、下载增长或收入。

- **诉求**：用户直接描述的问题。能证明问题出现过，不能证明现在所有版本都存在，也不能代表市场普遍性。
- **参照**：其他项目已提供的功能，说明有可参考的产品/技术路径，不等于新的市场空白。
- **提案**：结合 SheetDelta 当前缺口提出的产品判断，尚需通过实际接入验证。
- 历史 Issue 与近期讨论分开记录。已关闭 Issue 仍可作为需求历史，不当作竞品当前缺陷。同一作者的模板保真跨社区发帖只作为一个信号。
- 下文 P0 为下一阶段优先，P1 为核心流程完成后建设，P2 为按实际案例决定。S/M/L 表示相对实现复杂度，不是工期。

## 2. 已有能力：继续维护，不重复开发

| 领域 | 当前已提供 | 明确边界 |
| --- | --- | --- |
| 文件读取 | CSV/TSV、XLSX/XLS；表头行、工作表选择、源行号；原始值/显示值选项 | 普通 Excel 读取在内存中完成；不自动猜日期/编码 |
| 数据比较 | 复合键、左右列名映射、忽略列、绝对数值容差、字段级文本规则、类型/空值策略、列结构差异 | 需要唯一键；没有多对多业务匹配、相对容差或汇总对账 |
| 数据质量 | 必填、类型、唯一、范围、枚举、正则；清洗审计、显式去重 | 缺必需列独立约束、自定义跨字段规则、异步查重与错误工作簿 |
| 合并 | left/inner/full join、冲突策略、纵向追加与来源索引 | 不支持多对多连接；合并与比较的键类型语义不同，需显式规范化 |
| 导出 | 数据 XLSX、带颜色的差异 XLSX、CSV；CSV 默认防公式注入 | 普通导出没有完整的业务报表配置层 |
| 大文件 | CSV 流式读写、单表 XLSX 流式写、Node 本地 XLSX 流式读、有序流比较 | 流比较要求先排序；共享字符串有上限；浏览器 XLSX 读取仍在内存中 |
| 工作簿 | 定点改值/公式、保留未修改包内容、请求重算、受支持公式缓存重算 | 不插入模板明细行；不自动更新复杂对象；不编辑加密或签名包 |
| 公式 | 29 个常用函数、引用、跨表依赖、循环检测 | 是明确子集；已有 LibreOffice 对照中的混合类型差异记录 |
| 接入与验证 | ESM、TS、子路径隔离；比较进度/取消；Worker 源码示例；Node 多版本 CI | Worker 示例不等于完整文件流程 SDK；尚无全面 Excel/WPS 实机矩阵 |

核对文件：[类型与比较选项](../../packages/core/src/types.ts)；其他依据为 `packages/core/src/{validate,clean,merge,excel,stream,workbook}.ts`、`apps/docs/`、`.github/workflows/ci.yml`、`playwright.config.ts`。准确的可点击入口见文末“本地依据”。

## 3. 网上有哪些具体诉求

| 观察到的诉求 | 一手来源与时间 | 对 SheetDelta 的判断 |
| --- | --- | --- |
| 必须出现某列，但该列允许空值 | RSI #257，2024-05-21，查询时 open。[S02] | 增加独立列结构规则；不能复用单元格 required 冒充 |
| 保存银行等固定来源的列映射、表头位置，重复使用 | RSI #188，2023-08-01，查询时 open。[S03] | 建设版本化导入配置，避免每次手工配置 |
| 需要真实数值，不想反解析带货币格式的显示文本 | RSI #279，2025-07-17，查询时 closed。[S04] | 原始值/显示值已有；补原始数值词法保留和明确精度策略 |
| 输入的是选项名称，系统要的是内部 ID | RSI #275，2025-03-11，查询时 closed。[S05] | 建设字典映射，区分展示标签与实际值 |
| 希望支持 Vue 3 | RSI #274，2025-02-25，查询时 open。[S06] | 优先提供无框架核心与 Vue/React 示例，降低 UI 绑定成本 |
| 伪装为 CSV 的 HTML 导致异常后界面一直加载 | RSI #260，2024-06-10，查询时 open。[S07] | 文件流程必须有终态、可解释错误与资源回收；是回归用例方向 |
| 重复键需要明确报错或策略，不能产生难理解的比较结果 | csv-diff #31，2022-07-25。[S08] | 目前默认拒绝已覆盖；补业务分组诊断，而非静默丢弃 |
| 差异结果需要导出 CSV，方便下游命令行处理 | csv-diff #39，2024-09-20。[S09] | CSV 已有；可建设 CLI、稳定结构化报告格式 |
| 使用流式 API 仍遇到内存增长 | ExcelJS #2916，2025-04-09，报告者使用 4.4.0。[S10] | 扩大宽表、慢目标、背压、共享字符串测试；不直接断言该问题根因 |
| 浏览器解析/写入大文件卡住，需要 Worker 和进度 | ExcelJS Discussion #3013，2026-01-06。[S11] | 将现有比较 Worker 示例扩展为可复用文件任务 API |
| 上游 Excel 列名/顺序不同，导入数据库前需要映射和跨列校验 | r/webdev 原帖及评论，检索页显示约 9 个月前。[S12] | 支持映射、跨字段规则与错误修复循环；数据库写入由宿主负责 |
| 修改 Excel 后希望保留格式，同时避免内存问题 | r/learnjavascript 原帖，2025 年历史讨论。[S13] | 已有定点保留；可扩展受限模板填充，不承诺任意工作簿无损编辑 |

这些信号支持优先打磨业务流程。它们没有证明“所有 Excel 功能都应该收进包里”，也没有证明用户愿意付费或广告能变现。

## 5. 实施顺序与完成条件

不要把 34 项全部塞进下一版。每个阶段都应形成可独立使用的流程，并在结束时重新核对实际反馈。

| 阶段 | 选取能力 | 对开发者交付什么 | 进入下一阶段的条件 |
| --- | --- | --- | --- |
| A：导入纠错完整流程 | I02、I03、V01、V05、V06、C05；R03/R04 持续开展 | 一个无框架示例完成“供应商 Excel → 映射 → 校验 → 错误报告 → 修正重试”；业务代码无需重写解析/定位逻辑 | 缺列但无数据、空值、重复键、错误格式、取消均能解释；错误报告往返后 ID 与来源正确 |
| B：可重复的日常业务 | I04、I05、I06、V03、V04、E01、E02 | 固定导入配置、明确日期/金额、带说明的模板和报表；商品/库存/订单各有可执行示例 | 配置版本升级有兼容策略；金额不静默舍入；Excel/WPS 已测范围可见 |
| C：前端体验和大文件 | I01、V02、R01、R02、C08、E04、R05 | 浏览器能取消，Node 能处理乱序大文件；多表输出和批量业务校验 | 慢输出、磁盘满、共享字符串大、取消时无残留；承诺容量由公开可复现测试支撑 |
| D：高级对账 | C01、C02、C03、C04、C06；按需 V07、I07、R06 | 汇总差异、批量文件、规则复用、集成稳定性 | 至少有针对性的真实接入案例验证必要性；不改变原比较默认语义 |
| 候选池 | I08、C07、E03、R07 | 特殊报表、版本管理或自动化场景 | 有明确用户文件结构或使用流程再做，不靠想象扩大支持范围 |

R03、R04 不应因阶段表而被延后：它们是每次文件能力变更的验证工作。获取不到某应用时，保留未测标记；不把生成器往返测试当作实机结果。

最先做的 6 项功能是：**列映射、列结构检查、跨字段校验、错误工作簿、流程编排、来源追踪**。先打通这 6 项，并补相应可靠性验证，再扩展报表和性能。

## 7. 需要守住的 API 设计约束

1. **一个包，按需入口**：优先扩展已有 `/validate`、`/clean`、`/compare`、`/excel`；真正职责独立时再考虑 `/import`、`/report`、`/worker` 等候选入口。这些路径尚未实现。
2. **按需打包不等于按需安装**：`exports`/tree shaking 可以隔离浏览器代码，但普通 dependencies 仍随包安装。UI 框架、可选 schema/decimal 适配不能无条件扩大所有用户的依赖；新增 peer 依赖前验证 npm/pnpm/yarn 行为。
3. **原始值与转换值分开**：来源信息作为伴随元数据，避免插入用户列名中发生碰撞。不得默默把 `001`、大整数、空值或日期转成另一种含义。
4. **配置可保存，函数不可随意序列化**：JSON 配置只允许声明式规则；自定义函数用调用方注册表绑定规则 ID，不能对配置里的字符串执行 eval。
5. **保留默认语义**：比较与 join 的现有类型行为都要保留。新的统一键策略只能显式启用，并给出迁移说明。
6. **严格描述内存与取消**：异步不等于流式，流式不等于常数内存；全表唯一性/外键检查需要状态。记录预算和中止边界，不隐藏索引成本。
7. **承诺可验证**：每项新能力同时带可运行例子、错误用例、浏览器/Node 边界和中英文文档。未实现的功能只能出现在路线图中。

## 8. 暂缓或不纳入核心

| 方向 | 决策与原因 |
| --- | --- |
| 全功能在线 Excel 编辑器 | 暂缓。公式编辑、撤销、渲染、协作是另一套产品；现有定位关注业务数据流程 |
| 完整 Excel 公式兼容 | 暂缓。维护现有 29 函数和明确错误策略；新增函数由实际模板驱动，并加入独立对照样本 |
| 无主键模糊匹配、自动多对多对账 | 暂缓。可先做候选提示与人工确认；自动错配业务记录的代价高，尚无本次调研足够证据支撑优先级 |
| 图表设计器、透视表编辑、图片提取/插入 | 暂缓。优先保留已有对象；复杂对象编辑只在具体报表需求出现后评估 |
| 加密解密、数字签名编辑、宏执行 | 不纳入近期核心。保留清楚的检测和不支持错误；宏内容保留不代表执行宏 |
| PDF/OCR 转 Excel、AI 自动修数 | 不纳入近期核心。涉及识别与推断，不能在导入对账时无声修改原始业务事实 |
| 数据库/CRM/Google Sheets 托管连接器 | 核心只接受输入并返回结果；网络账号、写库事务、权限和同步由宿主或后续独立适配负责 |
| 所有历史表格格式、移动端任意超大文件 | 按真实样本逐项验证；不以“支持所有格式/无限大小”作为产品承诺 |

## 9. 建设效果如何判断

这一阶段优先衡量能否接入和是否正确，不用新增函数数量评估完善程度。

- 同一个库存/商品导入实例，开发者需要自己写多少映射、校验和报错代码；新增 API 是否减少重复逻辑。
- 固定问题集的定位准确性：错误必须回到原文件正确位置；清洗不能改变未指定字段。
- 上传到结果的流程能否处理失败和重试；重复执行产生相同的结果与来源信息。
- 在公开测试矩阵中记录支持/未测/失败项；固定样本性能可复现，变化可解释。
- 收集真实接入中的阻塞项，再决定 P2。尚未开展用户访谈或收集真实接入数据，不假设有现成的付费需求。

后续推广时，映射检查器、校验器、对账工具、报表模板示例可以使用同一核心服务文档站访客；先让工具本身有用，不强迫 npm 使用者访问网站，不在包里植入广告或未经同意的文件上传。
