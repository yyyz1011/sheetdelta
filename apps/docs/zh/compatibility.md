# 兼容性与性能

## 已验证的范围

仓库测试覆盖 CSV/TSV 引号与 BOM、XLSX/XLS 读取入口、XLSX 数据与差异报告导出、类型与复合键、校验、清洗、合并、取消以及子路径依赖隔离。既测试源码，也单独安装打包后的 npm 产物验证。

独立 XLSX 样本由 **openpyxl 3.1.5** 生成，覆盖前导零和长文本编号、1900/1904 日期系统、布尔值、物理空行、隐藏表、标题及数据合并区域、错误单元格，以及有缓存和无缓存的公式。GB18030 CSV 样本用于检查明确指定编码的读取。参见[样本源码与来源](https://github.com/yyyz1011/sheetdelta/tree/master/tests/fixtures)。

这些是项目自建、由另一套工具生成的合成文件，不代表已验证每一个 Excel、WPS 或 LibreOffice 版本。已有 XLS 测试和导出回读也使用了解析引擎的写入器，属于回归检查，不能视为独立格式认证。

Worker 示例经过浏览器目标打包和类型检查，消息、进度、取消流程通过 Node Worker 传输适配层执行。现有浏览器工具有独立 Playwright 回归测试；它们不代表新增 Worker 示例经过所有浏览器认证。

## 可复现的比较基准

安装依赖后运行 `npm run bench:core`。脚本构造固定规则的数据，校验比较汇总并测量两个 API；不包括文件解析、Worker 数据传输、网络或 XLSX 导出。

一次本地测试：**2026-09-09，Apple M4，macOS arm64，Node 25.9.0**。每侧 5 列，1% 的记录改变，`includeUnchanged: false`，异步批次为 2048。

| 每侧行数 | 同步比较 | 异步比较 | 保留差异行数 |
| --- | --- | --- | --- |
| 10,000 | 26 ms | 53 ms | 100 |
| 50,000 | 112 ms | 334 ms | 500 |
| 100,000 | 199 ms | 503 ms | 1,000 |

单次测量仅说明这个样本和设备的表现，不是性能承诺，也不是与其他包的排名比较。异步调度会增加耗时，以提供进度和取消机会。CPU、列数、文本长度、变化比例和垃圾回收都会显著影响结果。脚本还输出堆内存差值，但该数值不是峰值内存。

## 使用边界

- 数组 API 和模板修改在内存中保留数据。专用流式 API 增量处理，但共享字符串和行宽仍影响内存；异步数组比较本身并非流式。
- Excel 原始日期是带日期系统元数据的序列数，显示模式返回格式化文本；不会自行推断时区转换。
- `readExcel` 读取公式缓存；专用计算模块支持文档列出的公式和依赖，不实现完整 Excel 函数库。
- `writeExcel` 和流式导出创建新数据文件，`patchWorkbook` 为现有模板保留未触及的包内容；不编辑加密或带数字签名的文件。
- 提高限制前，请用贴近业务且不含敏感信息的样本验证。精确小数场景使用规范化文本，或在库外采用合适的小数策略。

参见[导入策略](./excel)、[异步与 Worker](./async)和[升级行为变化](./migration)。

## XLSX 流式测量

运行 `npm run bench:stream -- 1000000`。在相同 Apple M4 / Node 25.9.0 环境、5 列、**V8 堆上限 128 MiB** 下，一次测试写出 1,000,000 行用时 **7,574 ms**，逐条读取并核对编号、行号用时 **7,533 ms**。XLSX 文件大小 **26,442,063 字节**，采样进程峰值 RSS **259 MiB**；RSS 包含 V8 堆以外的内存。输入逐条生成、文件通过 pipeline 写出、读取时不收集完整数组。

10 万行的一次测试写出 616 ms、读回 700 ms，采样峰值 RSS 166 MiB。这些是本地单次测量，不是固定内存或耗时承诺。共享字符串很多、单行很宽或目标写入很慢时，成本不同。读取器会明确拒绝超出限制的共享字符串字典。

仓库 CI 中的独立安装检查覆盖 Node 18、20、22、24，浏览器目标打包单独检查。根入口继续保持轻量，浏览器依赖关系中不包含仅供 Node 的读取器。
